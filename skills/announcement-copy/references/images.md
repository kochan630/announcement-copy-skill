# 告知画像を確認してから生成する

## 画像が担う役割を選ぶ

本文や確定した提供内容から、役割の異なる案を2〜3案出す。絵柄だけを変えた案にしない。

- 作業を想像してもらう画像：実際のノートや画面、教材の見本。実物が必要なら提供を依頼する。生成した画面を実際の製品画面や受講成果と呼ばない。
- 内容を短く伝える画像：何を整理し、何を試すのかを示す図。単純な関係図ならSVGなどの編集可能な形式も適する。
- 告知用のメイン画像：見出しが読める余白を設けた写真・イラスト。架空の人物や会場を、実際の講師・参加者・会場と誤認させない。

## 生成前に確認する内容

一度の確認に、選びやすい具体案をまとめる。

```text
用途：告知ページのメイン画像
案A：ノートが整理されていく様子を表すイラスト
案B：実際のノート画面を使った説明画像（元画像が必要）
案C：当日の実習内容を示す図
推奨案と理由：今回の内容と読み手に合わせて記載
画像に入れる文字：確定した見出しだけを転記
サイズ・枚数：掲載先に合う寸法と枚数
構図・色・余白：具体的に記載
API・モデル・画質：使用するサービスと設定
費用：公式料金と想定条件を案内。計算できなければ金額未確認と明記
確認事項：どの案で、この条件の画像生成を進めますか？
```

未確定の日時・金額を推測して画像に入れない。承認済みの範囲で進め、構図や用途・費用が変わる別案は確認する。素材不足でも本文は仕上げられる。

## OpenAI APIを使う

Python 3.10以上。外部Pythonパッケージは不要。モデルの利用権限とAPI利用料金は、ClaudeやChatGPTの会話用契約と別に確認する。

1. `examples/image-plan.json`を作業用フォルダにコピーし、確定した画像案で編集する。`generation.prompt`は実際にAPIへ送る指示であり、構図・用途・文字・制約を反映する。上の説明欄だけを編集して済ませない。
2. APIのモデルと料金を[公式モデル一覧](https://developers.openai.com/api/docs/models)と[料金](https://developers.openai.com/api/docs/pricing)で確認する。例の`gpt-image-2`は対応モデルの例であり、最新版・最安という指定ではない。
3. 次を実行し、送信内容・出力先・計画のSHA-256を確認する。これはネットワークを使わず、APIキーも不要。

```bash
python3 /path/to/announcement-copy/scripts/generate_image.py --plan /path/to/image-plan.json
```

4. 利用者に画像案と生成条件を提示し、生成の了承を得る。SHA-256を指定する操作だけで、会話での了承を代替したと扱わない。
5. `OPENAI_API_KEY`をローカルの環境変数に設定する。値をチャット・計画・リポジトリに書かない。
6. 承認された計画のSHA-256をそのまま指定して実行する。計画を変更した場合はプレビューからやり直す。

```bash
python3 /path/to/announcement-copy/scripts/generate_image.py \
  --plan /path/to/image-plan.json \
  --execute --approved-sha256 承認済み計画のSHA256
```

CLIは新規PNG画像1枚を生成する。出力先は計画JSONの場所を基準に解決する。既存の画像や実行記録がある場合は止まる。失敗・タイムアウト時も自動再送しない。課金や生成状況を確認し、必要な場合だけ新しい出力名と再実行の了承を使う。画像編集や参照画像入力はこのCLIでは対応していない。

画像と同じ場所に`.request.json`の記録を残す。そこには生成指示を含むため、公開範囲を確認する。記録や出力の保存に失敗した場合も、API側では実行済みの可能性がある。

## 生成後

画像を開き、告知に使うサイズで確認する。

- 確定した文言・日付・価格に合っているか。文字の誤りや欠けがないか。
- 小さく表示したときも見出しが読めるか。端が切れても必要な情報が残るか。
- 実物と誤解される画面や人物、無断のロゴが混ざっていないか。

日本語や細かい日時を正確に置く必要がある場合は、背景だけを生成し、文字を編集可能なレイヤーで組む方法を提案する。背景生成だけで完成した告知バナーと報告しない。完成画像・生成指示・確認結果・保存先を返す。

## API仕様の参照
